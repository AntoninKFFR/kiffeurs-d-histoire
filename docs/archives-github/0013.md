## Contexte
Une partie solo = 10 questions par défaut, 30 secondes maximum chacune, avec ou sans compte (PRD : Parcours joueur, Comptes). La bonne date n'est révélée qu'après la réponse ; l'heure du serveur fait foi pour le chrono.

## Objectif
Des fonctions SQL (RPC) permettent de lancer une partie selon des filtres, de répondre à chaque question et d'obtenir le résultat, sans jamais exposer une réponse à l'avance.

## Tâche pour l'agent
Lis `CLAUDE.md`, `docs/prd.md`, `docs/architecture.md` §5 (Solo), et la doc Next.js 16 dans `node_modules/next/dist/docs/` avant toute route serveur.
1. Tables `histoire.games` et `histoire.game_questions` (événement, ordre, `asked_at`, `deadline`, réponse, précision, points). `user_id` nullable pour les parties sans compte, avec un jeton secret stocké en cookie `httpOnly` côté Next.js.
2. RPC `start_game(filtres)` : filtres = pack, thème/tag, période (années), niveau et chapitre, difficulté, nombre de questions (10 par défaut). Tire des événements `playable` compatibles avec la difficulté, sans doublon.
3. RPC `next_question(game)` : renvoie titre, description sans date, illustration ; fixe `deadline = now() + 30 s`.
4. RPC `submit_answer(game, {year, month?, day?})` : refuse après la deadline, calcule via `score_answer`, renvoie la bonne date, l'écart, les points.
5. RPC `finish_game(game)` : précision moyenne et total.
6. Server Actions Next.js minces qui appellent ces RPC (pas de logique de score en TypeScript).

## Critères d'acceptation
- [ ] Une partie complète se joue en local par script ou test, avec et sans compte
- [ ] Impossible d'obtenir la date d'une question avant d'y avoir répondu (test)
- [ ] Une réponse après 30 s vaut 0 point
- [ ] Lint, types, build verts
