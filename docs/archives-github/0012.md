## Contexte
Le PRD (section « Score et chrono ») fixe une formule à calibrer plus tard :
- précision P = 100 × max(0, 1 − écart / E₀), E₀ = 50 ans (Facile), 36 mois (Moyen), 90 jours (Difficile) ;
- points = P × (0,7 + 0,3 × temps restant / 30), 0 sans réponse à 30 s ;
- mode inversé : 100 % si bonne réponse, 0 % sinon, même bonus de rapidité.
Le score doit être calculé en base, jamais dans le navigateur.

## Objectif
Une seule fonction SQL de score, partagée par tous les modes, dont les paramètres sont modifiables sans toucher au code.

## Tâche pour l'agent
Lis `CLAUDE.md`, `docs/prd.md` (Score et chrono, Cœur du jeu), `src/lib/game/dates.ts` (calcul d'écart existant).
1. Crée une table `histoire.scoring_settings` (E₀ par difficulté, poids précision/rapidité, durée du chrono) avec les valeurs du PRD.
2. Écris `histoire.date_gap(...)` (écart en années, mois ou jours, avec dates av. J.-C., sans année 0) et `histoire.score_answer(...)` qui renvoie précision et points.
3. Gère les événements à précision plus faible que la difficulté demandée (ex. événement connu à l'année en mode Difficile) : la question ne doit pas être posée, ou l'écart est compté dans l'unité disponible. Documente le choix.
4. Ajoute des tests SQL (pgTAP ou script `supabase/tests/score.sql`) couvrant l'exemple du PRD : armistice 1918, réponse 1914 en 10 s en Facile → 92 % et 83 points.

## Critères d'acceptation
- [ ] Tests SQL verts en local, y compris l'exemple du PRD et une date av. J.-C.
- [ ] Les paramètres se changent par une simple mise à jour de `scoring_settings`
- [ ] Rien hors du schéma `histoire`
