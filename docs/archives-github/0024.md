## Contexte
Comptes (PRD) : ce sont ceux de KFFR contrée (même projet Supabase). On joue sans compte, mais rien n'est conservé ; avec un compte, scores, chapitres et statistiques sont enregistrés. La page `/connexion` (e-mail + mot de passe) existe déjà. Interdiction de modifier les schémas `public` et `auth`.

## Objectif
Un joueur peut se connecter (ou créer un compte), et ses parties sont rattachées à son profil.

## Tâche pour l'agent
Lis `CLAUDE.md`, `docs/prd.md`, `docs/architecture.md` §2, `src/app/connexion/` et la doc Next.js 16.
1. Inscription (`/inscription`) et mot de passe oublié, via Supabase Auth, sans rien toucher hors `histoire`.
2. Création automatique d'une ligne `histoire.players` (pseudo) à la première connexion sur ce jeu.
3. Une partie jouée sans compte peut être rattachée au compte si le joueur se connecte à la fin de la partie (bandeau de 3.4).
4. En-tête : pseudo, accès au profil, déconnexion.

## Critères d'acceptation
- [ ] Un compte KFFR existant se connecte et voit son pseudo
- [ ] Une partie finie puis « Se connecter pour sauvegarder » apparaît dans l'historique du joueur
- [ ] Aucune migration hors du schéma `histoire`
- [ ] Lint, types, build verts
