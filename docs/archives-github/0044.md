## Avant
Le score n'existait qu'à titre d'exemple dans le navigateur (page d'aperçu), avec une formule qui n'était pas celle du PRD.

## Après
La base calcule elle-même la précision et les points d'une réponse, avec la formule du PRD :
- `histoire.scoring_settings` : une ligne de réglages (E₀ = 50 ans / 36 mois / 90 jours, 70 % précision + 30 % rapidité, chrono de 30 s). Pour recalibrer : `update histoire.scoring_settings set max_gap_years = 40;`
- `histoire.date_gap(...)` : écart en années (`YEAR` = Facile), mois (`MONTH` = Moyen) ou jours (`DAY` = Difficile), av. J.-C. compris, sans année 0.
- `histoire.score_points(précision, secondes)` : la formule commune des points, que le mode inversé appellera avec 100 ou 0.
- `histoire.score_answer(...)` : unité utilisée, écart, précision et points d'une réponse datée.

**Choix pour un événement moins précis que la difficulté** (ex. connu à l'année, posé en Difficile) : l'écart est compté dans l'unité disponible, avec l'E₀ de cette unité, et la fonction renvoie l'unité réellement utilisée. Le tirage des questions (2.2) devra éviter de poser ces questions ; ce n'est qu'un filet de sécurité. Documenté dans `docs/architecture.md`.

Ces fonctions ne sont pas appelables depuis le navigateur : les fonctions de partie de l'étape 2.2 s'en serviront. Les réglages, eux, sont lisibles (pour afficher la durée du chrono).
