## Contexte
La migration de départ crée `events`, `event_aliases`, `themes`, `event_themes`, `players`. Le dataset v18 d'Antonin (`content/dataset-v18/`, voir `content/README.md`) est plus riche : dates début/fin, précision, `playable_mode`, importance/difficulté 1-5, niveaux scolaires, 46 chapitres du programme, 24 packs prêts à jouer, tags.

## Objectif
Le schéma `histoire` peut stocker tout ce dont la V1 a besoin dans le dataset, et rien n'expose les dates ni les alias au navigateur.

## Tâche pour l'agent
Lis `CLAUDE.md`, `docs/prd.md` (sections Contenu, Modes), `docs/architecture.md` §4, `content/README.md` et les en-têtes des CSV `kiffeurs-events-v18`, `themes`, `curriculum-links`, `ready-collections`, `ready-collection-events`, `tags`, `event-tags`.
1. Crée une migration (`npm run db:new modele_dataset_v18`) qui fait évoluer le schéma `histoire` : identifiant texte `EVT-xxxx` conservé, dates début/fin (année négative = av. J.-C.), précision, `playable`, `playable_mode`, importance, difficulté, description ; tables `levels`, `chapters` (thèmes du programme), `event_chapters`, `packs` et `pack_events`, `tags` et `event_tags`.
2. Sépare ce qui est lisible par le client (titre, description, image, niveau, chapitre, pack) de ce qui ne l'est pas (dates, alias) : vue publique sans dates, ou colonnes protégées ; les dates ne sont lues que par des fonctions `security definer`.
3. RLS activée sur toutes les nouvelles tables, lecture publique uniquement sur ce qui ne révèle pas de réponse.
4. Mets à jour `supabase/seed.sql` pour qu'il reste valide (10 événements de test).
5. Mets à jour `docs/architecture.md` §4.

## Critères d'acceptation
- [ ] `npm run db:reset` passe en local
- [ ] Un client avec la clé publique ne peut lire ni les dates ni les alias (test SQL ou script fourni dans la PR)
- [ ] Rien hors du schéma `histoire`
- [ ] Lint, types, build verts
