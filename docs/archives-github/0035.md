Closes #5

## Avant
La base ne savait stocker qu'un événement simplifié (année/mois/jour, un thème) et laissait le navigateur lire les dates : n'importe qui pouvait récupérer les réponses avec la clé publique. Elle ne pouvait pas accueillir le dataset v18 d'Antonin (niveaux, chapitres, packs, tags, dates de fin…).

## Après
Le schéma `histoire` peut recevoir tout le dataset v18, avec les identifiants d'Antonin (`EVT-0173`, `THM-001`, `COL-0059`, `TAG-0001`) :
- `events` (lisible) : titre, type, précision, statut de date, `playable`, `playable_mode`, importance, difficulté, image ;
- `event_answers` et `event_aliases` (**fermées au navigateur**) : dates de début et de fin, date en toutes lettres, **description** (elle cite la date dans 1 542 cas sur 2 000), alias ;
- `levels` (les 11 niveaux, remplis par la migration), `event_levels`, `chapters`, `event_chapters`, `packs`, `pack_events`, `tags`, `event_tags` (lisibles, sauf les tags de siècle posés sur un événement, qui donnent presque la réponse).

Seule la fonction `security definer` `check_event_answer` lit les alias ; les fonctions qui corrigent les dates et montrent la description après réponse viendront avec le moteur de jeu (2.1).

La page d'accueil n'affiche plus de dates (elle ne peut plus les lire) : titres des 20 événements les plus importants et nombre total.

Les anciennes tables `themes`/`event_themes` et les 10 événements de test sont remplacés ; `supabase/seed.sql` charge 12 vrais événements du dataset (avec niveaux, chapitres, packs, tags), que l'import 1.2 mettra simplement à jour.

## Comment tester
1. `npm run db:reset` puis `npm run db:test-securite` : affiche « OK : anon ne voit ni dates, ni alias, ni descriptions » puis la même ligne pour `authenticated`.
2. Ou, sur n'importe quelle base, coller `supabase/tests/reponses_invisibles.sql` dans le SQL Editor (tout est annulé à la fin).
3. Sur l'aperçu Vercel (base de test) : la page d'accueil liste 12 titres, sans dates.
