## Contexte
Décision de Maxou et d'Antonin (22 oct. 2026) : **une seule liste d'amis pour les deux jeux**. Kiffeurs d'Histoire réutilise les amis, la présence et les invitations de KFFR contrée (mêmes comptes) au lieu de recréer les siens. Les salons et les parties d'Histoire restent dans le schéma `histoire`.
Les tables concernées appartiennent à la contrée (schéma `public`) : **les agents de Kiffeurs d'Histoire n'y écrivent jamais**. Tout changement côté `public` se fait dans le dépôt de la contrée, par Antonin.

Ce qui existe déjà (lu en base le 22 oct.) :
- `friendships`, `friend_requests` et les RPC `send_friend_request`, `accept_friend_request`, `decline_friend_request`, `cancel_friend_request`, `remove_friend`, `get_friend_profile`, `list_invitable_friends` ;
- `social_presence` (`user_id`, `last_seen_at`), `touch_social_presence`, `get_my_friend_presence` ;
- `game_invitations` (liée à `room_id` des salons de la contrée), `send_game_invitation`, `accept_game_invitation`, `decline_game_invitation`, `get_my_game_invitations`.

## Ce dont Kiffeurs d'Histoire a besoin
1. **Amis** : pouvoir appeler les RPC d'amis depuis le site d'Histoire (mêmes droits qu'aujourd'hui). Rien à changer si elles marchent déjà pour tout compte connecté.
2. **Présence** : savoir **dans quel jeu** et **dans quel état** est un ami : hors ligne / en ligne / dans un salon / en partie, pour la contrée **et** pour Histoire. Par exemple une colonne `game` (`contree` | `histoire`) et `status` dans `social_presence`, renseignée par `touch_social_presence`.
3. **Invitations** : pouvoir inviter un ami dans un **salon d'Histoire** (le salon vit dans `histoire`, son identifiant n'est pas un `public.rooms.id`). Par exemple une colonne `game` + une référence de salon libre (texte ou uuid sans clé étrangère), ou une RPC dédiée.
4. Notifications temps réel : les invitations d'Histoire visibles par le destinataire comme celles de la contrée.
