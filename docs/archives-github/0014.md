## Contexte
Mode inversé (PRD) : le jeu donne une date, le joueur écrit l'événement. Correction tolérante déjà présente en base (`histoire.normalize_answer`, `histoire.check_event_answer`, similarité `pg_trgm` ≥ 0,6). Score : 100 % ou 0 %, avec le bonus de rapidité.

## Objectif
Le moteur de partie (2.2) gère aussi le sens inversé, avec les mêmes filtres et le même chrono.

## Tâche pour l'agent
Lis `CLAUDE.md`, `docs/prd.md` (Mode inversé), la migration initiale (fonctions de correction) et le travail de l'étape 2.2.
1. Ajoute un paramètre `sens` (`date` ou `inverse`) à `start_game`.
2. En inversé, `next_question` renvoie la date formatée (et sa précision) mais ni le titre ni la description.
3. `submit_answer` accepte un texte, utilise `check_event_answer` et renvoie le titre attendu et sa description.
4. Exclure les événements dont la date est partagée par plusieurs événements du tirage (réponse ambiguë).
5. Tests : « Guerre froide », « la guerre froide », « guere froide » acceptés ; un autre événement refusé.
