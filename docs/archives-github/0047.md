## Avant
La page /connexion proposait uniquement l’email et le mot de passe. Un joueur utilisant Google sur Contrée ne pouvait pas utiliser ce parcours sur Histoire.

## Après
« Continuer avec Google » et un séparateur « ou » sont ajoutés au-dessus du formulaire existant. Le callback /auth/callback échange le code PKCE et enregistre la session dans les cookies SSR de Histoire. Le retour utilise l’origine Histoire et conserve un next interne validé ; les URL externes, doubles slashs, backslashs, encodages dangereux et boucles d’authentification sont refusés. Les erreurs permettent de réessayer sans afficher les détails OAuth.

Le formulaire et l’action email/mot de passe restent inchangés. Le principe reprend lib/authRedirect.ts, lib/authCallback.ts et le parcours Google de Contrée, avec un Route Handler adapté aux cookies SSR de Histoire. Aucun appel à ensureProfile, aucun changement SQL, migration, db push ou configuration Supabase distante. Aucun changement aux fichiers des chantiers #11 et #12 ni aux branches de Max.

Le Dashboard du projet bskyfdjwcdvzhlugtknb a été vérifié en lecture seule : https://k-iffeur-d-histoire.vercel.app/** et les règles de previews Histoire sont déjà présentes. Aucune URL de production à ajouter, aucune modification de la Site URL Contrée. Les variables des previews peuvent pointer vers le projet de test de Max : vérifier le projet utilisé avant un essai Google réel. Détails dans docs/connexion-google.md.

## Comment tester
1. Ouvrir /connexion sur un déploiement Histoire utilisant le projet KFFR, cliquer « Continuer avec Google », terminer le parcours et vérifier le retour à l’accueil Histoire avec une session.
2. Ouvrir /connexion?next=%2Fapercu et vérifier le retour à /apercu après Google. Une URL externe ou /auth/callback dans next doit ramener à l’accueil.
3. Refuser Google ou appeler /auth/callback sans code : message d’erreur Google et possibilité de réessayer.
4. Vérifier la connexion email/mot de passe et son erreur existante.
